# Agent Note: 知识阅读与来源比较

Status: implemented

[English](2026-09-05-knowledge-reading-comparison.md) | 中文

## Problem

省略章节并截断证据的地图会让长回答比原始对话更难检索。回答之间的文字差异不能证明修正或矛盾，缺少较早页面则可能让旧内容看起来像新增内容。

## Decision

工作区首先呈现研究问题、原文回答摘录、已记录结果的限制和产物。可搜索、按轮次筛选的来源列表能到达每张已加载卡片；标题层级保留没有正文的父章节。阅读模式使用原回答的引用定义渲染完整 Markdown 块，并且只在浏览器偏好中保存选中卡片与阅读偏移。结构地图使用共同的节点矩形与连线端点，提供可滚动画布、缩放以及显示数量的工具折叠。没有详情列时仍可使用这些控件。

自动比较要求历史已完整加载且最新回答完整。相邻已完成回答之间按标题原文与上级标题精确配对；有重复候选时不配对。结果区分相同文字、文字变化、新出现的摘录和未再提及的摘录。这些观察都不证明语义关系。并列原文展示依据，让用户针对可能的矛盾、修正、关系或限制起草问题。放入草稿要求输入框空闲且没有内容，并且不会发送消息；正常对话提交记录所有模型可见输入。

[来源决策](../architecture/2026-09-05-knowledge-source-provenance.zh.md)继续约束可信内容和来源标识。[工作区提案](../../proposed/architecture/2026-09-05-knowledge-workspace-presentation.zh.md)保留专用全历史投影与结构化摘要生产者。明确加载历史提供完整比较材料，而不增加另一条传输路径或模型请求。

## Verification

来源样本覆盖新增、矛盾与修正表述、相同回答、重复标题及不完整历史。图布局样本验证 10、50 和 200 个节点的矩形不重叠且端点连接。GUI 与浏览器场景覆盖语义 Markdown、摘录之外的定义、键盘及列表导航、窄视窗、阅读恢复、来源动作与草稿转入。这些检查证明行为，不证明提议的五人理解效率与发现价值指标。

## Alternatives considered

**把每次文字变化分类为已修正主张。** 拒绝：措辞、范围和证据可能独立变化；语义判断必须对照两份来源明确核查。

**静默选取少量地图节点。** 拒绝：稀疏画面会错误暗示完整覆盖。数量、范围控件与完整来源列表明确揭示省略。

**每次阅读都生成模型摘要。** 拒绝：阅读不能创造未记录的权威或额外请求。结构化生产者需要记录来源和独立生命周期。

## Consequences

- 来源导航在窄视窗仍可使用，并独立于右侧详情列。
- 标题变化可能让相关材料无法配对；用户可手动选择原文，而不依赖猜测关系。
- 加载完整的大型 Session 会消耗浏览器内存与分页时间。专用投影仍是独立的架构决策。
