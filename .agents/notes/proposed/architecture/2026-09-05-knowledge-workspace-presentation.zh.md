# Agent Note: 知识工作区呈现

Status: proposed

English | [中文](2026-09-05-knowledge-workspace-presentation.md)

## Problem

Web 客户端为每个会话提供一个线性的聊天视图。`ChatSnapshot` 为滚动排列节点，`AppFrame` 提供全局侧栏、中央栏和工具详情栏，而未选择工具调用时右栏没有有用的默认内容。

因此，大型助手回答的结构只能通过阅读发现。用户不能先看到回答的主要结论、决策、行动、风险或引用；不能在不丢失上下文的情况下回到某一节；也不能将工具结果与使用它的结论进行比较。

## Proposal

已加载窗口实现遵循[来源决策](../../implemented/architecture/2026-09-05-knowledge-source-provenance.zh.md)及[阅读与比较决策](../../implemented/feature/2026-09-05-knowledge-reading-comparison.zh.md)。[手动整理决策](../../implemented/feature/2026-09-05-manual-knowledge-organization.zh.md)提供有界结构化生产者和持久地图投影。下述完整章节点投影、协调导航和评估目标仍属于提案。

Web 客户端新增知识工作区 Conversation View。它把会话投影为一个 `KnowledgeDocument`，其章节、卡片、关系、摘要、行动、风险和引用都具有稳定的不透明标识符。

呈现层在三个协同区域消费该模型：`sidebar.knowledge` 导航器列出可展开的章节树并跳转到卡片标识符；中央栏以摘要优先的卡片和细节展开来呈现内容及阅读进度；通用详情宿主呈现执行摘要、所选卡片上下文和已保存书签。现有工具检查器成为一个详情宿主贡献者，而不再独占整个右栏，同时仍由[客户端工具呈现权责](../../implemented/architecture/2026-08-08-client-tool-presentation-ownership.zh.md)负责工具专属呈现。

Conversation View 列表还包含图谱视图。它把问题、回答章节、工具调用、产物和引用呈现为相连节点，而选择会路由回工作区中相同的卡片标识符。图谱用于导航，而不是第二份转录。

`KnowledgeDocument` 由 Host 派生，并通过现有会话投影机制传输。确定性的首个提取器读取持久化助手 Markdown 标题、列表、链接、工具引用和回合边界。它立即生成大纲，不发起额外模型请求，并把不可用字段标为缺席。后续的结构化摘要器会在助手消息落定后记录版本化的 `knowledge/document` 会话事件；它提供精简的执行结论、决策、行动项、风险和卡片摘要，但不会替换原始回答。

阅读状态保持在浏览器本地：展开的卡片、聚焦章节、滚动进度和书签以持久化卡片标识符为键。该视图恢复读者的位置，而不把私人的阅读手势变成会话事实。书签标签日后可以成为显式的持久化用户产物，但首个实现不作此推断。

每个工作区控件、空状态、展开标签和呈现层拥有的错误都遵循[语言字典拥有客户端 UI 文案](../../implemented/architecture/2026-08-23-locale-owned-client-ui-copy.zh.md)。提供方和工具负载仍作为本地化产品外框下的事实细节保留。

## Component topology

`dsh-knowledge-presentation` 定义投影 DTO、Markdown 提取器、图谱链接和客户端类型出口。它的 Host 提供方注册会话投影；它的 Web 消费方拥有 `KnowledgeDocument` 选择器，绝不在浏览器中折叠会话事件。

`dsh-client-ui-knowledge-workspace` 注册 Conversation View、导航器 slot 和详情宿主贡献者。`ui-layout` 拥有中立详情宿主和选择状态；`ui-chat` 作为一个贡献者提供现有工具检查器。`ui-sidebar` 声明 `sidebar.knowledge`，使工作区导航器与工作区/会话浏览并列组合，而不是替换它。

## Delivery plan

1. 引入类型化 `KnowledgeDocument` 投影与确定性提取器，并提供 fixture 驱动的 Host 和客户端测试。
2. 将右栏泛化为详情宿主，保留工具检查器，并添加本地化执行摘要贡献者。
3. 将导航器和卡片阅读器添加为知识工作区 Conversation View，包括跳转、折叠、聚焦、进度和本地书签行为。
4. 使用相同标识符和导航回调添加图谱 Conversation View。
5. 添加结构化摘要生产者、它的持久化事件、版本迁移策略，以及证明重新打开会话后可重建同一知识地图的快照。

## Alternatives considered

**仅对 ChatView 进行 CSS 重设计**——不予采纳：更窄的气泡和可折叠 Markdown 不会创建共享标识符模型、导航器、执行摘要或图谱，因此用户仍须靠滚动发现回答。

**只在浏览器中解析 DOM**——不予采纳：已挂载的行会分页和虚拟化，刷新会丢失结果，图谱也会与紧凑转录不一致。Host 投影为每个客户端区域提供同一个可回放模型。

**从第一版起为每个回答发起第二次模型请求**——不予采纳：在工作区提供基本导航之前，这会增加延迟、成本和另一条失败路径。确定性提取器立即给出标题和引用；结构化摘要仍是明确的后续生产者。

**替换聊天转录**——不予采纳：原始消息、实时流行为和工具时间线仍是必要证据。工作区是同一会话上的一个选定 Conversation View，而不是有损转换。

**持久化每个阅读交互**——不予采纳：滚动位置和展开状态是私有且高频的偏好。只有有意创建的未来书签产物才值得持久化协作语义。

## Acceptance criteria

- 含有长 Markdown 回答的会话会打开一个知识工作区视图，在读者遍历完整转录之前展示主题树、执行摘要区域、卡片、引用和图谱入口。
- 选择导航器项或图谱节点会聚焦中央栏中同一张卡片，不会替换会话或丢失原始转录。
- 工具检查器、摘要上下文和书签通过独立注册的贡献者在右栏共存。
- 重新加载会从持久化会话材料重建同一投影文档；浏览器本地阅读偏好只为当前浏览器用户恢复。
- Web profile 为每个新的产品字符串提供本地化的英文、简体中文和繁体中文副本。
- 聚焦投影、客户端 GUI、记录会话和无障碍测试证明常规、空、摘要不可用和长回答路径。

## Risks

- 部分回答没有 Markdown 标题或标题不一致。首个提取器必须生成一张无标题卡片并清楚标记不可用的摘要字段，而不是编造结构。
- 若助手回答被编辑或重试，结构化摘要可能过时。其事件必须命名来源助手落定，而消费者必须拒绝来源标识符不匹配的摘要。
- 图谱可能变得密集。它必须默认展示章节级节点、折叠工具调用组，并提供相同的导航器聚焦路径，而不是要求用户平移浏览每个事件。
- 移动详情宿主会改变共享 slot 约定。迁移必须先保持当前工具详情行为正常渲染并受测试覆盖，然后再启用知识贡献者。
